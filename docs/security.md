# 运行安全边界

Mini-dsh 是面向可信开发环境的原型。`WorkspaceFiles` 使用目录 FD 和 `O_NOFOLLOW` 拒绝路径穿越与符号链接；`.env` 和指定 DeepSeek 凭据文件受文件工具保护。Shell 只接受 argv 数组和显式白名单，子进程超时会清理进程组，输出返回有界片段；配额以内保存完整产物，超额时只保留已捕获部分。权限策略默认禁止写操作；评测任务显式授予工作区写权限。

普通 `run` 未设置 `--docker-image` 时，Shell、测试、构建和模型 bridge 在宿主机运行。内置 Git 工具目前仅允许 `status`、`diff` 和 `log`，不提供 Git 写操作；但 Shell 可间接调用 Git，取决于白名单。MCP server 也是宿主机进程，且可能有外部副作用；必须使用可信配置。MCP server 的 stderr 丢弃以避免无限制临时文件增长，不能通过 Trace 审计其诊断输出。文件工具的路径限制不限制这些进程自身的文件访问。

Docker 评测使用无网络、只读容器根目录、去除 Linux capabilities、`no-new-privileges`、内存与进程限制，工作区仍可写，容器仍共享宿主机内核。不能把它视为抵御任意恶意代码的强隔离。Docker daemon 的访问权本身很高，只应授予可信操作者。

API Key 的精确值在 Session Event、Context 和产物中脱敏；其他凭据、PII、任意工具输出及异常信息仍可能进入 Trace。`Trace` 与 `.runs` 默认不提交，但操作者必须保护运行目录。新建运行目录为 0700，Trace 文件为 0600。文件工具单次读写上限为 1 MB；子进程每次最多捕获 16 MiB 输出，超过时清理进程组并返回错误，已捕获的片段可作为审计产物；单 Session 产物默认配额为 512 MiB。模型输入和 Trace 仍可能消耗较多内存，Session 总文件数没有配额。恢复机制只从完整工作区检查点继续，并拒绝不确定工具结果、变化的工作区与外部模型桥接器。工作区哈希无法证明外部系统状态，因此 MCP、Shell 和 Git 的外部副作用仍需人工核查。详见 [恢复机制](resume.md)。

实验 ZIP 会原样包含任务 Manifest、基线源码、Trace 和工具产物，不做额外脱敏或加密。任务 Manifest 可能含模型不可见的留出测试断言；归档只供评测方保存，不能挂载到 Agent 工作区。默认放在 Git 忽略的 `.exports/`，新导出文件以 0600 权限创建。验包限制归档路径、文件数量和解包大小，并在临时目录解包；这些限制不等于对任意恶意 ZIP 的完全隔离。归档内自带的哈希可检测意外损坏；防止归档与哈希同时被重写，必须另存可信锚点并使用 `--trusted-anchor` 检查。
